How These Numbers Are Defined

  • Every date is the date the authorization was completed (Date Auth Completed Roll Up), not the date it was requested. So this dashboard measures throughput — what finished in the window. A request that arrived in August and finished in September counts in September.
  • Total Authorizations — authorizations completed in the selected window, matching the current Type, Status, Portal and Provider filters. Type is matched case-insensitively (the export mixes Appointment with DIAGNOSTIC).
  • Easy Schedules / Hard Schedules — the two halves of what used to be the single Appointment type. A scheduling authorization is a hard schedule when its Encounter Provider is on a fixed roster of providers whose appointments are known to be difficult to schedule, and an easy schedule otherwise. Together they are exactly the old Appointment total — nothing is added or dropped, and both are selected by default. The roster is not written down anywhere on this page, but it can be read off the Provider filter: pick one provider and see which half its appointments fall into.
  • Portal — Insurance Portal, the payer portal the authorization was worked in. (Blank) is a real answer rather than missing data: it is mostly Auth Not Required work that never needed a portal, and it holds almost no RPA activity.
  • Provider — Encounter Provider, the provider on the encounter, scoping every figure on the page. (Blank) is again a real answer and roughly a quarter of all rows: those authorizations carry no encounter provider, which is why the filter opens with it included. Unlike every other filter here these are people's names, so treat the page accordingly — it is restricted for that reason among others.
  • N/A appears wherever a filter has no values ticked. That is a filter state, not a measurement: nothing has been asked about, so nothing is reported. A genuine zero — a window or a slice that really holds no authorizations — still shows as 0.
  • Touched by RPA — distinct rows where RC Assigned contains svc-quickbase or Bot Run Fail Date is populated. Rows with both are counted once.
  • RPA Success Rate — rows where RC Assigned contains svc-quickbase, over rows touched by RPA. A row with both a fail date and a bot assignment counts as a success after retry.
  • Date Presets are anchored to the latest date in the export, not to today, so a stale file still shows a populated window.
  • Failure reasons are normalized into categories; member and authorization identifiers present in the raw text are stripped before publishing, and only aggregate counts are shipped.
